# Security checklist

Review date: 2026-10-03. Inspection was against `/tmp/jobmatch-review` (branch `cursor/jobmatch-ai-cabb`). “Fixed” means the code in this review changed it. “Not found” means that area was inspected and the issue was not present.

| Issue | Found? | What was done | Final status |
| --- | --- | --- | --- |
| Hard-coded secrets | Not found. `AI_API_KEY` is read from the environment only. `.env` is gitignored. `.env.example` has empty placeholders. | No code change. | Not found |
| Exposed environment variables | Not found in API responses. `GET /api/health` reports `matcher: local` or `ai-with-local-fallback`. It does not return the key, base URL, or model. | No code change. | Not found |
| SQL injection | Not found as an exploit. Job, resume, and recommendation queries use `?` placeholders. A title of `' OR 1=1 --` was stored as text and did not change the job list. | No query rewrite. Input is still validated for length. | Not found |
| Unsafe raw SQL | Not found. `db.exec` runs only the fixed `CREATE TABLE` script in `backend/database/db.js`. Runtime statements are prepared. | No code change. | Not found |
| XSS | Stored markup was not executed. A title containing `<img src=x onerror=alert(1)>` rendered as text in Chrome and produced no page error. No `dangerouslySetInnerHTML`. | Resume display names now drop `<>` and other unsafe filename characters. Application URLs are checked before `window.open`. | Fixed for filenames and URL opens. React text rendering was already safe. |
| Unvalidated input | Partial. Title, company, and description had length checks. URLs were not length-limited and could include userinfo. Job ids used `Number()` on any digit string. | Server and client reject URLs over 2,000 characters, non-http(s) URLs, and URLs with a username or password. Control characters are stripped. Ids must match `^[1-9]\d{0,14}$` and `Number.isSafeInteger`. | Fixed |
| Unsafe uploads | Partial. Extension and a `%PDF-` check existed. Multer 1.4.5-lts.2 is deprecated and Snyk lists high-severity fixes in 2.2.0+. `npm audit` on the old tree reported 0 backend issues, so this came from the install warning plus the Snyk advisory, not from `npm audit`. | Dependency moved to `multer@2.4.0`. Uploads retested: text PDF accepted, `.txt` rejected, fake PDF bytes rejected, 5 MB+ file rejected, 26-page PDF rejected. | Fixed |
| Path traversal | A filename `../../etc/passwd.pdf` did not leave a file outside `backend/uploads`. Stored names were already generated. The original name was still kept from the client. | Display names go through `path.basename` and a character filter. `saveUpload` rejects a stored name that is not a basename. After the traversal attempt, `uploads/` contained only `.gitkeep`. | Not a successful write outside the upload directory. Filename handling tightened. |
| Oversized uploads | A limit of 5 MB already returned 400 “PDF must be 5 MB or smaller.” | Left the limit. Added a 25-page cap and a 100,000-character text cap. Multipart field/part limits were tightened. | Already enforced for bytes. Page and text caps added. |
| Unsafe URLs | `javascript:` and `ftp:` were already rejected. Credential URLs and very long URLs were not. The client opened `job.applicationUrl` with `window.open` without its own protocol check. | Server and client reject userinfo and overlong URLs. `openHttpUrl` allows only `http:` and `https:` and refuses userinfo. | Fixed |
| Excessive payloads | `express.json({ limit: '1mb' })` already returned 413 “Request is too large.” Description max is 20,000 characters. | No limit change. Confirmed with a ~2,000,000-character JSON title. | Not found as a missing control. Confirmed working. |
| Sensitive error messages | 500 responses already used a generic sentence. A bad database printed a stack in the server log, not in the browser. SQLite unique failures would have been generic 500s. | Database open failures log `JobMatch could not open its database (SQLITE_CANTOPEN).` with no stack. Unique conflicts return 409 without SQL text. `X-Powered-By` is disabled. | Fixed for the database log and constraint responses. |
| CORS | Allowed origins were listed, and a foreign origin did not get `Access-Control-Allow-Origin`. The handler still ran: a cross-origin POST created a job (201). Requests with no `Origin` (curl) are still allowed. | Middleware returns 403 “This origin is not allowed to call the API.” before routes when `Origin` is present and not listed. Re-test: status 403, job count unchanged. | Fixed |
| Dependency vulnerabilities | Backend `npm audit` after the multer upgrade: 0 vulnerabilities. Frontend `npm audit`: 2 moderate, both in `react-router` 6.x (`GHSA-wrjc-x8rr-h8h6`, `GHSA-337j-9hxr-rhxg`). The audit fix is `react-router-dom@7.18.4`, a major upgrade. This app does not pass user URLs into `<Link>` or `useNavigate`, and it does not use SSR hydration. | Multer upgraded and upload tests re-run. React Router was not force-upgraded. | Multer fixed. React Router left in place. |
| Unsafe database handling | Queries are parameterized. Foreign keys and WAL are on. Opening a directory as the database file crashed the process. | Startup catch exits with a one-line message. Confirmed log: `SQLITE_CANTOPEN`. The UI then shows the existing “Cannot reach the API” banner. | Open failure no longer prints a stack. The process still exits because the file cannot be used. |
| Server-side validation | Present for jobs and resumes. Gaps were URL length, URL userinfo, unsafe ids, recommendation body, and working-resume growth. | Those checks were added. Accepting recommendations now requires user wording and rejects placeholders. Working resume text is capped at 80,000 characters. | Fixed |
| Upload type, size, filename, traversal, invalid files | PDF-only filter, 5 MB limit, generated filenames, and `%PDF-` magic bytes were already there. | Re-tested after the multer upgrade and the filename sanitizer. Invalid types, invalid bytes, blank PDFs, oversized files, and too many pages fail with a short 400. | Enforced |

## Headers

API responses now send `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, and `Cache-Control: no-store`. `X-Powered-By` is off.

## Not claimed

No authenticated multi-user threat model was added. The app still has no accounts, by design. Curl without an `Origin` header can still call the API on the machine. A live OpenAI request was not sent. `npm audit fix --force` was not run.
